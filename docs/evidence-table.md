## 消融：每个模块到底贡献了什么

离线对照作用在**已建好的图**上，图固定，所以是精确因果而不是抽样。

| 模块 | 关掉之后 | 结论 |
|---|---|---|
| 别名合并 | 4,826 节点 / 1,256 分量 / 最大 2,905（60.2 %）/ 孤立 929 | 合并 407 个节点，分量 **1,256 → 1,087**、孤立 **929 → 822**，但最大分量 **2,905 → 2,829**。碎片变少、主分量略缩——因为被删的噪声节点原本挂在主分量上。**「合并只改善连通性」是错的** |
| 八类实体约束 | —（约束是提示词，没有代码闸门） | 仍有 **552 个节点（11.1 %）** 不在八类内（unknown 415、other 101、institution 19、person 5）。若严格执行，最大分量 **3,073 → 2,759（−314）**：不合规节点在承载连接，约束与连通性有冲突 |
| 策展本体 | 六维度回到 286/62/18/107/186/149 | 盖层 **18 → 58（3.2×）**；最大分量 **2,992 → 3,073**；代价是薄维度内连通率下降（断层 83.9 % → 75.9 %） |

复现：`python scripts/ablation.py --offline`（结果同时写 `eval/ablation.json`）。

**在线探针**：golden set 的 10 题没有一题给出断层倾角或注入速率，而阻断策略只在这两种输入下允许阻断——所以在那 10 题上关掉物理闸门是**空实验**（两组必然逐字相同）。为此加了一题探针（不参与 golden set、不用于算分）：2500 m / 420 bar / 倾角 60°。

| 臂 | 闸门 | physics | 重写 | 交付正文 |
|---|---|---|---|---|
| baseline | **failed** | violation | 2/2 用尽 | 166 字（正文被隔离，只剩阻断说明） |
| `no_physics_gate` | **passed** | pass | 2 | **1,897 字** |
| `no_rewrite` | failed | violation | 1 | 166 字 |

关掉物理闸门，一份「注入压力 420 bar 超过 2500 m 处破裂压力 379 bar、断层滑移比 2.199」的方案会拿到 1,897 字的「通过」报告。这就是它的贡献。

**`no_rewrite` 这一臂测不出贡献，如实记下**：golden 第 1 题上两臂都是 `passed`（1,398 vs 1,362 字，重写次数都是 1）——那题第一次判定就通过，重写预算没被用到。要测它需要一题「靠重写救回来」的用例，现在没有。同题两跑 `physics_status` 一次 `unverifiable` 一次 `warning`，说明抽取阶段有非确定性：**单例 + 本地 7B，组间差异未必大于噪声**，所以这一组只叫诊断。

口径：三组都在本地模型下跑（`eval_ragas` 的隔离环境，cloud 客户端置空、路由钉本地），样本 1 例，**是诊断不是基准**，绝对分数不可与云端比。

## 五件我要主动说的事

1. **偏差方向写反过一次。** `gap-register` 初版把「总应力固定 → 余量偏大（偏乐观）」写成了结论，方向是反的：按 `τ = √(s(1−s))·|σh − σv|`，注入抬高 σh 会让 τ 下降、σn 上升，所以总应力固定是**保守**一侧。已改正，并写进 `poroelastic.py` 的 docstring。写反比不写更糟。
2. **覆盖率曾经显示 0 %，原因是缺一个 import。** `corpus_audit.py` 把 `ImportError` 吞成 `(0,0,0)`，于是「没装 PyMuPDF」被报成「语料没入库」。现在退出码区分：1 = 指标不达标，2 = 环境缺依赖。
3. **389 实体那个数字在 README 里躺了几个月。** 语料涨了 11 倍，文档没跟着改，于是它变成了别人批评我的依据。现在 README 里所有历史数字都标了时点。
4. **第一次在线消融跑了 5 分半，表上写着「0 通过 / 0 失败」。** 那不是闸门失效，是 `.env` 里的 `CLOUD_API_KEY` 把报告阶段路由到云端端点、而该端点本机不可达，每一例都以 `APIConnectionError` 收场。差一点被我读成「关掉闸门后一个都没拦住」。现在三组统一在 `eval_ragas` 的隔离环境里跑（cloud 客户端置空、路由钉本地），并在结果里写明 `environment` 字段。**「零通过零失败」和「零阻断」长得一模一样，只能靠环境字段区分。**
5. **消融跑把真实的历史记录弄丢过。** 探针问句被写进 `project_history.md`，压缩逻辑按「最近 N 条」把它留下、把 120 条真实记录挤掉。根因是 `file_memory` 在 import 时就把路径固化成模块常量，之后再设 `PROJECT_HISTORY_PATH` 环境变量对它无效——我以为在 `_prepare_isolated_agent_environment` 里设了就够了。已从 git 恢复文件，并把隔离改成「环境变量 + 直接改已导入模块的常量」两件都做，配 5 项测试钉住（`test_ablation.py` / `test_eval_ragas.py`）。**测试数据污染个人历史是不可逆的，这比任何一个指标都严重。**

## 一句话

这个系统的价值不在于「能生成报告」——那部分任何人都能做；在于**它知道自己什么时候不可信**：闸门会硬阻断、UQ 会说「分辨不出」、求解器会说「无解」、消融会说明每个模块值多少。把这四件事说清楚，比再加一个模块有用。

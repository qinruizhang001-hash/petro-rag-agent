## 结论先行

六类批评里，**只有一条是归因错误，其余基本成立**——但成立不等于同等紧急。

最要紧的一条被说错了方向：**「知识规模偏小」的根因不是论文太少，而是每篇论文只喂了开头 4000 字符。**

| 指标 | 实测值 | 说明 |
|---|---:|---|
| 语料 PDF | 23 篇 / 542 页 | 与批评的「22–23 篇」一致；`ccus4.pdf` 是电信 NOMA 论文，显式排除 |
| PDF 原始可抽取字符 | 1,467,291 | PyMuPDF 直接抽到的字符，含参考文献与页码 |
| 清洗后正文（可喂入量） | 1,096,138 | 剥掉参考文献/页码后**这才是覆盖率的分母** |
| 实际入库字符 | 1,092,271 | **占清洗后正文 99.7%**（重建前 8.1%） |
| chunk 数 | 874 | 每篇 7–95 个，平均 1,657 字符（重建前 71） |
| 实体 / 关系 | 4,826 / 5,008 | 重建前 394 / 400（批评的「389/400」就是那个旧图） |
| 孤立节点 | 847（17.5%） | 平均度 2.08（重建前 15.5% / 2.05） |
| 文档血缘可追溯率 | **100%** | 23/23 篇可追溯到 `file_path`（重建前 0%） |

换句话说：**批评看到的 389 个实体，是一个只读了不到一成语料的系统产出的。**
把覆盖率从 8.1% 拉到 99.7% 之后，实体涨到 4,826（12 倍）、血缘从 0% 到 100%，
而孤立节点从 15.5% 涨到 17.5% —— 覆盖率上去了，连通性反而变差。
这条反直觉的结果正是 §1.2 的结论：**「提高覆盖」和「保持连通」是两件事。**

> 口径更正：本文件初版把覆盖率写成 6.2%，用的是「原始可抽取字符」做分母。
> 但参考文献和页码本来就不该进图（`clean_pdf_text` 主动剥掉 23%），拿它们
> 当分母等于把「主动不喂」算成「漏喂」。同时 `ccus4.pdf` 是故意排除的，
> 也曾被算进分母，导致覆盖率永远显示 96.9%。两处都已改到
> `utils/corpus.py` + `scripts/corpus_audit.py`，分母统一为清洗后正文。

## 一、先修正三条事实

### 1.1 截断是刻意的，但代价被低估了

`ingest_ccus_batch.py --graph-budget` 默认 4000 字符，代码里的理由是：

> LightRAG 每处理一个 chunk 就要跑一次 LLM 实体抽取，实测在 CPU 上约 31 秒/千字符。
> 20 篇论文全文（约 100 万字符）意味着 8 小时以上的推理 —— 不现实。

这个理由在当时成立，**但现在不成立了**：本机有 RTX 5060（8 GB），实测吞吐是
**10.64 秒/千字符**（`graph_ingest_state.json` 里 23 篇的真实 `seconds` 反算），
不是 31 秒。全量重建的时间估算因此从「8 小时」降到 **2.2–4.3 小时**。

### 1.2 多喂文字不会摊薄质量——这是实测的

拿同一篇论文（`ccus_auto_16.pdf`，9,210 字符）在两个隔离的临时工作目录各建一次图：

| | 预算 4000 | 全文 9,180 | 倍数 |
|---|---:|---:|---:|
| 耗时 | 39.6 s | 68.1 s | 1.72× |
| 实体 | 14 | 33 | 2.36× |
| 关系 | 13 | 32 | 2.46× |
| **实体密度（个/千字符）** | **3.50** | **3.59** | **1.03×** |
| 孤立节点占比 | 0% | 12.1% | — |

两点结论：

1. **密度几乎不衰减**（+3%）。截断丢掉的不是「低价值的尾段」，而是等密度的正文。
   这意味着 8.1% 的正文覆盖率不是「精选摘要」，是实打实丢了九成知识。
2. **但连通性不会自动变好**：全文喂入后孤立节点从 0 涨到 12%，连通分量 1 → 6。
   覆盖面扩大后，边缘实体更不容易挂到主图上。所以「提高覆盖」和「保持图谱连通」
   是两件需要分别做的事——后者靠本体约束与关系归一，不能靠多喂字。

### 1.3 血缘是 0%，不是「较弱」

23 篇文档的 `file_path` 全是 `unknown_source`，因为 `insert_text` 从没传
`file_paths`。后果不是报错，而是**知识库说不清自己从哪来**：报告里任何一句话
都无法回溯到 PDF，想撤掉某篇论文的影响只能整库重建。

已在本次修复（`lightrag_retriever.insert_text(..., file_paths=)` +
`ingest_ccus_batch` 传真实文件名 + `tests/test_lineage.py` 5 项回归）。
注意：**存量数据仍是 unknown_source**，要等下次重建才生效。

## 三、按性价比排序（建议 4 周）

排序依据：**能否用现有数据完成 + 是否有可测量的验收标准 + 是否直接回应批评**。

### W1 — 把 8.1% 变成 ~100%（最高性价比，只需机器时间）

- `--graph-budget 0`（全文）重建图谱，默认值已改为全文（见 `utils/text_cleaning.graph_text`）。
  实测端到端吞吐 **12.9–14.8 秒/千字符**（不是 A/B 短论文给出的 5.5 秒边际速率，
  那是低估），1,096,138 字符的正文约需 **4 小时**。
- **中断后续跑**：直接重跑同一条命令即可（已建图的篇目会 `[SKIP]`）。但如果进程是在
  某篇**处理到一半**时被杀，会留下 `full_docs` 有正文、`doc_status=processing`、
  零 chunk 的残留 —— 而 LightRAG 的去重只看 `full_docs`，重跑时直接 return 不报错，
  入库脚本却仍打 ✅。这种情况先跑
  `python scripts/repair_partial_ingest.py --apply` 清掉残留，再重跑。
  （实测踩到过一次：第 5 篇就是这样被静默跳过的。）
- 顺带修复：血缘（已改代码）、清掉 2 个未引用 collection、把 <200 字符的 chunk 丢弃。
- **验收**：`scripts/corpus_audit.py` 显示覆盖率 ≥95%、实体数 ≥3,000、血缘可追溯率 100%。
- **风险**：孤立节点占比会上升（实测 0% → 12%），需要在 W3 用关系归一压回去。

**结果（2026-10-25 实测，重建总耗时 3 小时 26 分）**

| 指标 | 重建前 | 重建后 | 门禁 |
|---|---|---|---|
| 正文覆盖率 | 8.1% | **99.7%**（1,092,271 / 1,096,138 字符） | ≥95% ✅ |
| 实体 | 394 | **4,826** | ≥1,000 ✅ |
| 关系 | 400 | **5,008** | — |
| 血缘可追溯率 | 0% | **100%**（22/22 篇） | 100% ✅ |
| 连通分量 | 1 | **1,169** | — |
| 最大分量占比 | — | 62.0%（2,992 实体） | — |
| 孤立节点 | 0% | **17.5%**（847 个） | — |
| 平均度 | 2.05 | 2.08 | — |
| chunk | 1,982 | 874（每篇 7–95，均 1,657 字符） | — |

三点必须说清楚：

1. **孤立节点没有停在预测的 12%，而是 17.5%**。覆盖率从 8.1% 拉到 99.7% 之后，
   新增的九成正文带来了大量边缘实体，它们没有挂到主图上。这印证了 §1.2 的结论：
   **「提高覆盖」和「保持连通」是两件事**，后者不能靠多喂字解决。
2. **连通分量 1 → 1,169 不是退化，是度量口径变了**。旧图只有 394 个实体且几乎全在
   一个分量里（因为读的正文少、实体少）；现在 4,826 个实体里有 847 个孤点，其余
   聚成 322 个多节点分量。判断图谱好坏要看「最大分量占比 + 平均度」，不是分量数。
3. **chunk 数从 1,982 降到 874**，因为 1,982 是三代 Chroma 集合的近似重复总量，
   而 874 是这次重建实际写入的图谱 chunk。两者不是同一个口径，别直接相减。

已知残留：`ccus_auto_17.pdf` 的 chunk-025 在实体抽取阶段返回了空 JSON
（`JSON extraction result is empty or unrecoverable`），该 chunk 贡献 0 实体。
这是单块失败而不是整篇失败，覆盖率的 0.3% 缺口主要来自它。

### W2 — 消融实验（回应「缺科研级基准」，不需要新数据）

- 三个开关 × golden set 10 题：本体约束（8 类 never-extract）开/关、
  时间层（`core/temporal.py`）开/关、UQ（蒙特卡洛）开/关。
- 指标：RAGAS Faithfulness / Answer Relevancy + 检索 Top-2 命中率 + 每千 token 成本。
- **验收**：一张 8 行（2³ 全组合）的表，每个数字可由 `eval_ragas.py` 复现。
- 这是**唯一能用现有资产产出「可写进论文的表格」**的一项。

### W3 — 结构化井史数据契约（回应「多井/多期次/区块级」）

- 定义 `well_record` schema（井号、日期、井深、注入压力、温度、层位、来源），
  加 CSV loader + 时序索引，让检索能按「井 × 期次」过滤。
- 不新增 Agent，只加数据模型与一个检索过滤器。
- **验收**：`ccus_docs/A1井_历史压力监测.md` 转成结构化记录后，
  提问「A1 井 2023 年 Q3 的压力」能精确命中，而不是靠向量相似度撞。
- **这是「区块级」真正的入口**——比再抓 20 篇论文有用得多。

### W4 — 治理最小集（回应「审计/脱敏/合规导出」）

- 日志轮转 + 归档（`logging.handlers.RotatingFileHandler`）。
- 报告级 lineage 段：每条结论附 `doc_id → file_path` 映射（W1 之后才拿得到）。
- 导出脱敏：导出前按正则抹掉坐标、井号、人名。
- **验收**：导出的报告里每个引用都能点回源文件；脱敏规则有单测。

### W5 — 物理深度（已完成，2026-10-25）

原批评第 3 条「物理只是规则校验，非多相流」是对的：`physics_rules` 就是
`P_inj vs P_h / P_frac` 的阶跃判定，看不到更早触发的失效模式。已补四层，
全部是确定性计算、纯标准库、带出处与假设：

| 层 | 模块 / 版本 | 判据 | 测试钉住的东西 |
|---|---|---|---|
| 地应力 / 断层活化 | `utils/geomechanics.py` 2026.10-g1 | Terzaghi 有效应力 + Mohr-Coulomb，`Pp,crit = σn − (τ−C)/μ` | 摩擦上限 `(√(μ²+1)+μ)²`（3.119 / 4.676）；最优产状 45°+φ/2 = 60.5°；两口径互证 places=3 |
| 盖层封闭性 | `utils/caprock.py` 2026.10-c1 | `Pc = 2γcosθ/r`、`H = Pc/(Δρ·g)`、`P_inj ≥ σhmin+T0` | 手算 43.3 bar；孔喉减半 Pc 翻倍；边界 0.98/1.02 翻转 |
| 两相流 | `utils/relperm.py` + `utils/flow1d.py` | Brooks-Corey + Welge 切线 + CFL 迎风 FV | 前沿 0.9138/0.9110；紧后方 0.3849/0.4045；守恒误差 0.0 |
| 模拟器接口 | `utils/reservoir_backend.py` 2026.10-b1 | `ccus-sim-result/1` 契约 + 解析筛查后端 | 未收敛拒绝、单位必须显式、两侧共用 validator |
| 物性 | `utils/co2_properties.py` 2026.10-p1 | Peng-Robinson + Span & Wagner Psat | 250 bar/80℃ = 662.9；20℃ Psat 57.4 vs 实测 57.3 |

**顺带修掉的一个数量级错误**：`ρ = 1.9·P/T` 在 250 bar / 80℃ 给 1.35 kg/m³，
真实值 662.9 —— 差 460 倍。这个数进浮力、流度比、重力分异，错 460 倍不是精度问题，
是把「封不住」判成「封得住」。同时它让所有「密度对得上」的校验都在跟一个错常数对齐。

**阻断策略（这是最需要克制的部分）**：深层判定依赖假设参数（应力梯度、孔喉半径），
用它阻断会造出另一类错误 —— 把没问题的项目拦下来。所以只在两种情况下允许阻断：
输入明确提到断层（带倾角），或明确给了 CO₂ 柱高 / 注入速率。其余只输出信息与敏感性，
理由写进 `policy` 字段随结果返回。

**仍然做不到的**（写在 README Roadmap，不写成「已支持地质力学」）：
三维应力转移、羽流形状随时间的重力分异演化、裂缝型泄漏通道、与求解器的在线耦合。
这几条仍然朝**乐观**那一侧，所以不能当安全裕度。

**2026-10-25 追加：把其中两条从「做不到」变成「算得出，并标清边界」**

| 原缺口 | 做法 | 偏差方向 |
|---|---|---|
| 孔隙弹性耦合 | `utils/poroelastic.py`：单轴应变应力路径 `Δσ_h/ΔP = α(1−2ν)/(1−ν)`，由 `σ_h = ν/(1−ν)σ_v + α(1−2ν)/(1−ν)P` 推导而来，不是抄公式。判定闸门**仍走保守口径**，耦合口径作为第二个数并列返回 | 耦合口径更宽松，但只对注入层成立；应力转移未建模，那部分可以在局部**降低** σ_h 并促进滑动 |
| 重力分异 / 柱高几何 | `utils/caprock.py`：给定圈闭面积时，同一批物质按 `A_trap` 而非 `πr²` 聚集，柱高与突破时间给出**区间**（圈闭为早界、一维为晚界） | 一维口径一直是乐观的那一侧；圈闭口径在存在溢出点时反而偏悲观 |

**顺带纠正一处口径错误**：本节初版把「总应力固定」写成「余量偏大」（即偏乐观）。
按闭式 `τ = √(s(1−s))·|σ_h − σ_v|`，注入抬高 σ_h 会让 τ 下降、σ_n 上升，所以
**总应力固定其实是保守的一侧**，方向写反了。修正后的说法写在
`utils/poroelastic.py` 的模块 docstring 里，并用 144 格网格逐点断言单调性
（`tests/test_poroelastic.py`）。这条错误值得记下来：偏差方向写反比不写更糟，
因为它会让人在错的那一侧放心。

### W6 — 不确定性量化深化（已完成，2026-10-25）

原批评「扰动模型较简单（均匀分布、输入独立），缺少参数相关性 / 更合理的先验 /
敏感性分析 / 用于决策阈值」四条都成立。逐条补齐，全部纯标准库、带解析基准：

| 缺口 | 模块 | 做法 | 测试钉住的东西 |
|---|---|---|---|
| 先验只有 uniform / normal | `core/uq.py` `Marginal` | 加 lognormal / triangular / beta，共 5 种，`perturbation_label()` 把分布名写进报告 | 方差对解析值：δ/√3、δ、√(e^{δ²}−1)、δ/√6、δ/√5 |
| 输入硬编码独立 | `core/uq.py` `JointSampler` | Gaussian copula：`z = L·g` → `u = Φ(z)` → `ε = F⁻¹(u)` | ρ_latent=0.8 → ρ_edge=0.787（理论 (6/π)asin(0.4)=0.786）；边缘方差不变 |
| 无敏感性分析 | `core/sensitivity.py` | Saltelli 一阶 + 总效应，Latin Hypercube 基样本 | `f=x1+2x2` → 0.20/0.80 且交互≈0；`f=x1x2` → 3/7 与 4/7 |
| 概率不进决策 | `core/risk_policy.py` | ok / warn / alert + 阈值可配置 + Wilson 区间 + `resolved` | 顺序反了 / 越界 / 非数字全部抛错；边界处 `resolved=False` |

**四个跑出来才知道的结论**（不是设计时想到的）：

1. **未中心化的 Sobol 估计量会把结论算反。** 教科书形式
   `mean(f_B·(f_AB−f_A))/V` 在可加基准（真值 S₂=0.80）上 N=4096 给出 **0.569** ——
   看起来像「压力不重要」，实际是估计器噪声：模型均值 300 bar 而标准差只有 6 bar，
   大数相乘把标准误放大到 0.79。改成中心化后同样的 N 给出 0.80。
   这是解析基准测试唯一的价值所在：没有它，0.569 这个数会一路进报告。
2. **三参数两两相关 0.9 是合法的。** 等相关矩阵特征值是 1+2ρ=2.8 与 1−ρ=0.1，
   正定。我最初的代码注释写成「必然奇异」，被反向断言纠正 —— 高相关 ≠ 非法矩阵，
   只能真的去 Cholesky，不能靠启发式判断。
3. **相关性能把风险判反方向。** 2500 m / 375 bar：独立抽样 P(压裂)=47%，
   ρ=0.9 时降到 **20%**。因为深度偏大时破裂压力同步偏大，正相关在这里是保护性的。
   而「独立」一直是硬编码的，也就是说在「深度与压力同源」的场景下，
   默认口径**高估了 27 个百分点**。
4. **N=100 在阈值附近没有分辨力。** 同一工况的解析真值 P=0.4016（数值积分，
   并用 N=100000 的蒙特卡洛交叉验证为 0.4023），三次 N=100 分别给出
   **0.35 / 0.43 / 0.47**。所以决策必须带 Wilson 区间与 `resolved` 标记，
   否则「恰好 5%」会被当成确定结论。

**偏差方向**：默认独立 → 在「深度与压力同源」的真实场景下**高估**风险（偏保守）；
在没有相关性的场景下无偏。阈值默认 5% / 20% 是**政策选择**，不是标准值 ——
ISO 27914:2017 与 DNV-RP-J203 都要求定义量化接受准则但不给数值，所以这两个数
可用 `UQ_WARN_P_LEAK` / `UQ_ALERT_P_LEAK` 覆盖，且报告必须写明来路。

**仍然做不到的**：相关输入下的方差归因（Sobol 在相关输入下无定义，代码直接报错
而不是给一个能被引用的数；替代方案是 Shapley 效应，代价是 d 倍模型评估）；
从数据反推 ρ（语料里没有配对实测）；把 UQ 传播进真实求解器（现在只过解析模型，
需要代理模型或批量运行模式）；`resolved=False` 时自动提高模拟次数（现在只报告
「需要多少次」）。

### W7 — 闭环注入策略优化（已完成，2026-10-25）

原批评成立：系统停在「评估风险 → 生成报告」，从不回答「那我该怎么注」。
张博组的 DRL 路线是**策略学习**（从「动作 → 反馈」里学策略），本项目**没有生产数据**，
照搬只会得到一个在自己模拟器里自娱自乐的智能体。所以补的是另一半：
**把处方写成可解的最优化问题，让求解器给答案，让模型只负责转述。**

**为什么是约束求解而不是让模型提建议**：生成式建议无法回代核对。
说「建议降到 320 bar」，没有任何东西能保证 320 满足预算，也无从检查它是不是
还能更高；预算不可达时，模型倾向于给一个折中值而不是说「无解」。
求解器没有这个自由度 —— 无解就返回 `infeasible`。

**决策变量为什么是压力上限，不是速率**：因果链是
`井底压力 p →（风险只由 p 决定）→ 压裂概率`，而 `p + 注入指数 J → 单井速率`，
`井数 n → 并联放大`。速率是 p 的下游产物。把速率当变量会让优化器在错误的
自由度上搜索 —— 它会把「关小泵」当成降风险的手段，而真正能同时保住速率的是
「多打一口井、把每口的压力压下来」。

**求解为什么不用二分**：泄漏判据是 `p(1+ε_p) > 1.5·P_h(d_i)`，
等价于 `p > 1.5·P_h(d_i)/(1+ε_p) ≡ P_s,i`。于是
`P(泄漏 | p) = #{P_s,i < p} / n`，即 `P_s` 的经验 CDF。
最大化满足预算的 `p` 就是取**次序统计量** `critical[k_max]` ——
没有容差、没有迭代次数、没有「没收敛」的歧义。

**约束用 Wilson 上界，不用点估计**：n=100 时 4.9% 的 95% 区间是 [2.0%, 11.4%]，
说「低于 5%」是假话。要求 `wilson_hi ≤ budget` 才叫合规。
代价是 n=100 时 0/100 的上界 3.6%、1/100 是 5.5%，约束退化成「零命中」，
所以优化器默认 **n=1000**（报告里仍是 100 次，两个数各有各的用途）。

**样本内 vs 样本外**：在同一批样本上求解再报告风险必然偏乐观 ——
挑的正是最有利的那个次序统计量。所以用 `seed + 7919` 抽第二批单独复核，
结果放在 `verification` 里，不并进主结论。

**实测（2500 m / 380 bar / 预算 5%）**：

| 项 | 值 |
|---|---|
| 当前 | 380 bar，P(压裂) **50.3%**，18.94 Mt/yr，1 口井 |
| 推荐 | **2 口井、316 bar**（破裂压力的 83%），18.94 Mt/yr（与当前持平） |
| 同井数下的压力上限 | 353 bar → 29.83 Mt/yr（比当前多 57%） |
| 样本外复核 | 0/1000，95% 上界 0.4% |
| 状态 / binding | `ok` / `risk` |

推荐语义固定为「**恰好**满足目标速率、最少井数」，余量单列 `headroom` ——
否则「推荐」会变成「在不超预算的前提下尽量多注」，那是另一个问题。

**主动披露的乐观假设**（写进 `notes`、报告 prompt、MCP 工具描述）：
`skin=0`（表皮系数取 0，实测 5 时注入能力只剩 63%）、无摩阻与非达西效应、
无井间干扰、风险只由压力决定、井位只是一条深度不是坐标。

**偏差方向**：注入能力**高估**（skin=0、无摩阻）、风险曲线是**阶跃不是斜坡**
（约 1.36×–1.66× 静水压力这条带内命中率从 0 到 1，带宽由 ±5% 扰动决定，
不是地质事实），所以「83% 破裂压力」这类数字只在当前扰动模型下成立。
无成本模型 → 只给前沿，不给唯一最优。

**风险口径与 UQ 模块逐样本对齐**：`TestSameRiskSemantics` 断言同 seed 下
`optimize` 的命中数与 `injection_risk_uq` 的 risky 命中数**逐样本相等**。
防的是「两个模块都自称有出处，却在报告里给出互相矛盾的数」。

**仍然做不到的**：随监测数据重解（一次性求解，不是控制器）、成本 / NPV 目标函数、
井位坐标优化（现在只是一条深度）、把 UQ 传播进求解器内部。

| 对接 CMG / Eclipse / TOUGH（**求解器本体**） | 需要商业许可与真实油藏模型。**契约层已经做了**（`ccus-sim-result/1`，见 §3 W5），因为契约可以在没有求解器的情况下被验证 —— 解析后端的结果要过同一套 validator。仍然不做的是「替模拟器跑一步、拿回压力再跑下一步」的在线耦合：没有许可就无法验证，写出来就是空壳，而空壳比没有更糟 |

## 五、一句话回答「离生产级差多远」

差三件具体的东西，不是差一个「更聪明的 Agent」：

1. **数据**：结构化井史/监测数据（W3），这是「多井多期次」的唯一来源；
2. **测量**：消融实验与对照基准（W2），没有它，任何「更好」都无法证明；
3. **治理**：血缘与脱敏（W1+W4），能源数据出厂的门槛。

物理深度已经交付到「筛查级」：能算断层会不会滑、盖层会不会漏、CO₂ 怎么推进，
并且每个数字都带着它依赖的假设。它**不是**场地级结论 —— 应力剖面是假设值、
孔喉半径是文献默认值、重力分异没建模。把「筛查」和「场地评估」混为一谈，
比完全没有物理层更危险，所以边界写进了 `limitations` 与 README Roadmap。

不确定性同样交付到「能被引用」为止：分布带分布名、敏感性带解析基准、
决策带阈值来路与 Wilson 区间。它**不是**「已经量化了风险」—— 相关矩阵靠人填、
阈值是项目政策而非标准、N=100 在阈值附近分辨不出 5% 与 8%。
把这三条写进报告，比把「P=12%」单独拎出来更接近工程实践。

闭环那一步交付到「**约束求解**」为止，不是「策略学习」：给定风险预算，能解出预算内
最高的井底压力、需要几口井、以及这个方案换一批样本还成不成立（样本外复核 0/1000）。
它**不是** DRL 控制器 —— 不随监测数据重解、没有成本模型（所以只给前沿不给唯一最优）、
井位只是一条深度不是坐标、注入能力按 skin=0 乐观估算。
把「可解的最优化」和「需要数据回路的策略学习」分开说，比把它们合并成一句
「已做闭环优化」更诚实。

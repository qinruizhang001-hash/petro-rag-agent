# CCUS 全链运维控制台 · 前端

目标只有一个：**让六态语义（含"不可判定"）在界面上站得住**，并且中央那块屏
描述的是物理状态，不是氛围。

- **第 1 周**（已完成）：左栏告警卡 / 指标卡接 `/api/ops/alarms` 的真实响应。
- **第 2 周**（已完成）：中央地质剖面（three.js + SVG 降级）、双模、语音状态环。
- **第 2.5 周**（已完成）：右栏知识库（语料清单 / 缺口 / 带出处的检索 / 切片原文）。
- **第 3 周**（已完成）：右栏对话（历史 / 发问 / 引用角标**跳转到切片详情**）、
  证据强度与数据来源指示、剖面图例与限制说明、告警本页处置标记（含沉底排序）、
  右栏可折叠（`?rail=off`）、三档窄屏适配、分段流式（`pending` 与 `retrieving`
  分开）、处置标记落本机（刷新不丢）、报告审批状态机（本机演练 / 已连后端两条路径）。
  **未做**：语音输入。

## 跑起来

需要 **Node ≥ 20.6**（写在 `package.json` 的 `engines` 里）。

这里踩过一个坑：原先测试脚本是 `node --test` 直接跑 `scripts/*.mjs`，而其中三个
（`test-quality` / `test-text` / `test-citations`）**直接 import `.ts`** —— 那要靠
Node 22.18 起默认开启的类型剥离。于是 `engines` 被顶到 `>=22.18`，CI 钉在 Node 20
就报 `ERR_UNKNOWN_FILE_EXTENSION: Unknown file extension ".ts"`：一个和逻辑毫无
关系的红，还顺带把"能不能在别人机器上跑起来"变成了一个运气问题。

现在测试用 `tsx --test` 跑，类型剥离交给 tsx，`engines` 降到 `>=20.6`。
**实测过，不是推断**：Node **20.20.2** 下 `npm test` 全过、`npm run build`
正常产出（`dist/assets/geoscene-*.js` 仍独立分块）。

```bash
cd web
npm install
npm run dev          # http://localhost:5180
```

默认读 `src/fixtures/*.json`，**不需要后端**。

要接真实后端：

```bash
# 后端先起在 127.0.0.1:8000（见仓库根 README）
VITE_OPS_SOURCE=live npm run dev
```

**起后端之前先给一份阈值**：`config/ops_thresholds.json` 不进仓库（里面是
某个项目的设计限值），模板是 `config/ops_thresholds.example.json`。不配的话
18 个测点全部"未配置阈值"，看板会显示 **18 项不可判定、0 需动作** —— 那不是
"系统正常"，是"没人定过线"。本地跑一遍可以这样：

```bash
OPS_THRESHOLDS_PATH=config/ops_thresholds.example.json \
  python -m uvicorn api_server:api --host 127.0.0.1 --port 8000
```

示例阈值里的 `source` 全是「【替换】…」，界面会原样显示 —— 这是故意的：
一份出处写着"【替换】"的阈值，比一份没有出处的阈值更接近可审计。

`vite.config.ts` 里把 `/api` 代理到 `OPS_API_TARGET`（默认 `http://127.0.0.1:8000`），
所以不需要为本地调试去开 CORS。

### URL 参数

一个只能靠点两下才能到达的状态，评审时总会有人截错图。所以下面这些状态都能用
查询参数直达：

| 参数 | 取值 | 说明 |
|---|---|---|
| `mode` | `deck` / `engineer` | 指挥舱 / 工程师。默认工程师 |
| `tab` | `section` / `chain` | 中央区的两个视图 |
| `voice` | `idle` / `listening` / `thinking` | 语音状态环的三种形态 |
| `rail` | `kb` / `dialog` / `off` | 右栏两个 Tab；`off` = 收起右栏（中央拿到全部宽度） |
| `kb` | `overview` / `search` | 知识库内部的概览 / 检索 |
| `q` | 任意问题 | 预填检索词。**只在 fixture 模式自动提交**，见下 |
| `perf` | `1` | 打开渲染开销面板，同时暴露 `window.__perf()` |
| `quality` | `high` / `medium` / `low` | 钉死渲染档位，关闭自适应降级 |
| `gpu` | `low` | 强制 `powerPreference: low-power`（尝试落到集显） |
| `ws` | `ws://…` | 指定推送地址，覆盖 `VITE_OPS_WS` |

```bash
npx vite preview --host 127.0.0.1 --port 4181
# http://127.0.0.1:4181/?mode=deck&rail=kb&kb=search&q=盖层完整性
```

`q` 只在 fixture 模式自动提交：live 模式下打开页面就跑一次 21 秒的检索，
会让"我刚点进来怎么卡住了"变成一个查不出原因的问题 —— 而它其实只是 URL 里带着参数。

## fixture 不是手写的

`src/fixtures/*.json` 由 `scripts/capture_ops_fixtures.py` 用 `TestClient`
向真实的 `/api/ops/*` 发请求抓下来的。重跑：

```bash
python scripts/capture_ops_fixtures.py           # 重新抓取
python scripts/capture_ops_fixtures.py --check   # 只比对（CI 用）
```

为什么值得这么麻烦：手写 fixture 会和契约悄悄分家。后端字段改名、枚举多一个值、
错误形状从 `{"detail": "..."}` 变成 `{"detail": {"message": ...}}` ——
这些都不会让任何东西变红，前端只是继续渲染那份"看起来还对"的旧数据。
`--check` 在 CI 里跑，接口一变就报出来。

场景是构造的，**阈值不是**：阈值直接取自 `config/ops_thresholds.example.json`，
一个数字都没改，`source` 里保留着 `【替换】` 前缀，界面上照原样显示
"这还不是你项目的真实阈值"。给示例阈值换一个像样的出处，是这套系统最不该做的事。

**羽流几何是示意值**，界面上同样照原样标注「示意（未接储层模拟）」。
它来自储层模拟，不是从压力读数反推的 —— 用 `reservoir_p` 去"推算"羽流半径，
得到的是一个看起来很像真数的编造值，而它会被截图放进汇报材料。

### 知识库 fixture 分两类，不能一视同仁

`src/fixtures/{overview,documents,search}.json` 由
`scripts/capture_kb_fixtures.py` 抓取，但它们的**可校验性不一样**：

| 文件 | 来源 | CI 逐字节 | CI 结构与自洽 |
|---|---|---|---|
| `overview.json` / `documents.json` | 纯文件读（`ccus_docs/`、`lightrag_storage/`、`chroma.sqlite3`） | ✅ 每次 | — |
| `search.json` | 真跑 LightRAG + Ollama，本机约 21 秒 | ❌ 没有 Ollama | ✅ 每次 |

**第二列和第三列是两件不同的事，必须分开说。** 逐字节比对问的是"这份文件
是不是当前后端会返回的那一份"，那要重跑检索。而证据包的**一大半是纯函数**：
来源表由切片按首次出现顺序去重得来、`stats` 是卡片计数、`text_quality` 由正文
算出 —— 这些都能离线重算，所以 CI 里查的是"**这份文件自己跟自己一致吗**"
（`kb_evidence.audit_evidence`）。

这一层抓的是一类比"内容过期"更安静的损坏：

- 手改一个 `reference_id` → 正文里的 `[3]` 指到别的文献，界面照常渲染；
- 删一条切片而忘了改 `stats` → 数字与卡片对不上，没人会发现；
- 把 `low` 从 `true` 改成 `false` → 「以公式为主」那个提示凭空消失。

过期的内容至少和当时的后端是一致的；被手改过的文件只和自己不一致。

脚本对 `search.json` 会**连着打印两行**：

```
未比对（逐字节）search.json：本机没有 Ollama，无法重建这份 fixture。…
已比对（结构与自洽）search.json：12 条切片 / 27 个实体 / … 查了顶层字段、问句指纹、来源表重算、stats 逐项、质量分、切片出处。
  这一层查不到的是「内容是不是当前后端会返回的那一份」—— 那需要重跑检索。
```

只说"未比对"会抹掉真做过的检查（下次有人删掉这段代码时不会有任何阻力），
只说"已比对"会替没做的检查背书。两个方向都安静，所以两句话都被
`tests/test_api_kb.py::SearchFixtureLayerTests` 锁着。

`search.json` 有 97 KB，是**动态 import** 的（`dist/assets/search-*.js`）。
改成静态 import 不会报错，只会让首屏多下载 78 KB，而这个面板在首屏是看不见的
（默认停在概览页）。CI 的 `KB search fixture is still code-split` 盯着这件事。

## 知识库面板：它要回答的不是"有多少篇"

是**"这个知识库能信到什么程度"**。所以三件事必须在首屏：

1. **缺口**。盘上 24 篇、图谱里 22 篇，差的那 2 篇按名字列出来，并说明后果
   （"检索不到它们"）。一个"共 22 篇"的数字读起来是完整的，而它其实漏了 2 篇 ——
   没有任何地方会提示这件事。
2. **可引用性**。只有图谱切片带 `file_path` 血缘，能点回原文；Chroma 那 1,982 条
   的 metadata 只有 `{"source": "legacy_v2"}`，**没有文件级血缘**。
   这件事写在界面上，否则用户会以为每条结论都能溯源。
3. **检索的三种状态长得不一样**。见下面第 6 条约束。

引用角标的语义也在界面上标死了：`reference_id` 是 **LightRAG 在一次响应内**
给来源编的号，同一个 `[3]` 在两次查询里指向不同文献。它能当"本次检索的第 3 个来源"，
不能存下来当书签 —— 要长期指向一篇文献只能用 `file_path`。

### 两种"点引用"是两件事

| 点哪里 | 去哪 | 为什么 |
|---|---|---|
| 正文里的角标 `[N]` | 知识库详情页（`KbDocDetail`） | 读者想知道"这句话出自哪"，他要上下文 |
| 「原文证据」列表里的编号 `[N]` | 同上（详情页） | 编号一律代表"出处"，点了去看出处 |
| 列表里的**文件名** | 就地展开这一片 | 他已经在看清单，点开是为了核对这一段，不该被带离对话 |

跳转时 `RightRail` 把 `{name, focus, fallback}` 交给 `KbSearch`。`fallback` 是
检索响应里**已经拿到的那一片原文** —— fixture 模式下 `/kb/documents/{name}`
不存在（12 篇全文是 MB 级），没有它，点一个角标只会看到"演示数据不可用"。
带 `fallback` 时详情页**不显示总片数**：那个数字没取到，显示成"共 1 片"
会把"缺数据"说成"数据是 1"。

**两个面板都常驻挂载**（`hidden` 切换而不是条件渲染）。条件渲染时点一个角标，
`DialogPanel` 会被卸载，它 `useState` 里的对话历史随之消失 —— 为了核对一句出处，
回来发现自己刚问的话没了。

### 右栏可折叠

`?rail=off` 直接进收起态。收起后栅格少一列、少一行，中央剖面从 345 px 涨到 679 px
（1279×900 实测）。收起用的是 `hidden` 而不是卸载，理由同上：对话历史不能因为
"看一眼剖面"就没了。顶部「‹ 知识库 · 对话」把它叫回来。

### 告警的处置标记会沉底

标记「已确认 / 已忽略」之后，卡片背景压暗一档、标题降一档，并**排到列表末尾**。
读数与左侧等级色条**不动** —— 已确认不等于问题消失，把一条 critical 调淡会让
下一个人以为它不用看了。沉底用两段稳定分区而不是 `sort` 比较函数：未处理之间
的相对顺序必须原样保留，读者记住的是"第三条是环空压力"。

## 八个必须守住的约束（外加一条前置原则）

### 前置 · 缺席不能被渲染成合格

这一条排在所有约束之前，因为它是这套界面的**唯一失败模式**：不是画错颜色，
是把"没查"画成"查过没问题"。同一个形状在三处出现过，三处都必须有独立样式：

- 测点没配阈值 → `indeterminate`（灰 + 虚线 + 破折号），不是 `normal`
- 注入压力上限缺读数 → `CeilingCard` 的 `indeterminate` 态，**不画进度条**
  （一条 0% 的条会被读成"压力很低"，而实际是"算不出来"）
- `ceiling` 字段整个缺失 → 显示"未执行"，并写明"未执行 ≠ 合规"

第三条尤其容易漏：字段缺失是 `undefined`，而 `undefined` 在 JSX 里渲染成空 ——
空白看起来像"这一栏不需要"。所以 `CeilingCard` 对 `null` / `undefined` 有独立分支。

同一原则的推论：**不可判定的原因不要在前端重新枚举**。`CeilingCard` 的折叠区
直接显示后端 `basis[0]`，展开区从 `basis[1]` 开始 —— 因为后端新增一种
"算不出来"的情形（例如"峰值时刻没有生效的破裂压力测定"）时，前端那句
手写的"缺井底压力或破裂压力读数"会**悄悄变成不完整的**，而它读起来
和之前一样确定。原因只有一个来源，展示层只负责选哪一行。

### 1. 六级，不是五级

`indeterminate` 不属于 `normal..critical` 那个序列 —— 它否定的是"能判定"这件事本身。
界面上是**三重信号**：灰 + 虚线边框 + 破折号。少任何一重，
色觉障碍用户或强光下的现场都会把它读成"正常"，而"把不知道渲染成没事"
是这套界面唯一不会报错的失败。

### 2. Tailwind 类名不能拼

`text-sev-${token}` 在运行时是对的，但 Tailwind 是**编译期扫描源码文本**生成 CSS 的。
它扫不到模板字符串，那批类名根本不会进产物 —— 症状是颜色全失效、文字继承父级，
而且没有任何报错。所以 `lib/severity.ts` 里有一张 `SEVERITY_CLASS` 字面量表。
加新状态时**两处都要改**，CI 还会 grep 产物确认六个类名都在。

### 3. 品牌色不进数据层

中石化红 `#D8232A` 与 critical `#B23A3A` 的色相只差 4°，同屏会把"品牌"读成"严重告警"。
品牌色只允许出现在页眉细线 / Logo / 客户联合品牌位 / 面板角标。
数据区永远是青、钢蓝与六级语义色。

### 4. 装饰不能吃掉数据

`html[data-mode="engineer"] .fx { display: none }` 这种规则，一旦标错元素，
删掉的就是数据而不是动效。**羽流本身是数据**（它表示 CO₂ 波及范围），
工程师模式关掉的是粒子与 3D 包络体，不是羽流。
剖面里唯一的判断标准是：这个图元如果消失，有没有一条结论会跟着消失。

**标签重叠是同一个故障的另一副面孔。** 测点标签的屏幕位置由世界坐标投影得出，
而"盖层完整性 / 地表形变 / 近地表土壤通量 / 浅层地下水"这四个测点在深度上挨得
很近（0–100 m）—— 画布一矮就叠成一团。每个字都还在，但没有一个能读。
它不报错、不消失，只是从"六个读数"变成"一片字"。所以 `lib/labels.ts` 里
`placeLabels()` 会把重叠的标签沿垂直方向推开：

- **只推测点标签**。层名（"盖层（泥岩封闭）"）的语义是"贴在这条边界线上"，
  推离边界之后它就在标注一条错误的线，那比重叠更糟；深度尺同理。
  它们只作为**障碍物**参与判断。
- **固定的先占位**。否则固定的排在后面时它不推别人、自己也不动，
  会留下一个消不掉的重叠（这个 bug 实测出现过）。
- **`x` 永远不动**。横向是测点在图上真实位置，动了就是在说谎。
- **推得太远就放弃**（`maxShift`）。飞出画布比重叠更糟——重叠至少还读得到一半。
- 标签尺寸每 30 帧重测一次并缓存：每帧读 `offsetWidth` 会强制同步布局。

实测 1279×900 下重叠从 4 处降到 **0**；900×1200（画布只有 320 px）剩 1 处
副标题交叠，主标题均可读 —— 17 个标签 × 24 px 在 320 px 高的画布上物理放不下。

### 5. 3D 必须保持懒加载

`three` 压缩后约 130 KB gzip，用动态 `import()` 拆成独立 chunk。
左栏的告警卡是"这个班次要不要叫人"的全部依据，它不该等一个 3D 库下载完才出现。
CI 的 `3D scene is still code-split` 一步会断言独立 chunk 存在、首屏 chunk < 320 KB ——
改成静态 import 时"左栏先亮"会静默消失，没有报错，只是工控机上多等一秒。

### 6. `empty` 与 `unavailable` 不能合并

检索有三种结果，不是两种：

| 状态 | 含义 | 界面 |
|---|---|---|
| `ok` | 检索到内容 | 证据卡 |
| `empty` | 检索跑完了，确实没有相关内容 | 「图谱里没有相关内容」 |
| `unavailable` | 检索没跑起来（Ollama 未启动 / 图谱未初始化） | 「检索未连接」+ 原因 |

把第三种渲染成前两种里的任何一个，操作员都会去补文献 —— 而真实原因只是
Ollama 没启动。所以后端对 `unavailable` 也返回 **200**（不是 503）：
它是需要被看见的**系统状态**，不是请求错误；返回 503 的话前端只会弹一个
通用报错，操作员学不到"是模型没起"还是"是库空了"。

这与 `indeterminate ≠ normal` 是同一条约束，只是发生在检索层。

### 7. 渲染开销有上限，超了要自己降档

"在集显上能跑 60 FPS"是一句必须能被证伪的话。没有测量，它就只是一句写在
文档里的承诺；而下一次有人把 3000 个粒子改成 30 万个、或者把 `pixelRatio`
上限从 2 改成 `devicePixelRatio` 时，没有任何东西会红。

集显是个很宽的区间（Intel UHD 620 与 Iris Xe 差三倍，插电与省电模式又差一倍），
所以**不能调到一个值，只能给一个能自己往下走的台阶**：

| 档位 | pixelRatio 上限 | 粒子 | 3D 包络体 | 数据图元 |
|---|---|---|---|---|
| `high` | 2 | 有 | 有 | 全部 |
| `medium` | 1.25 | 有 | 有 | 全部 |
| `low` | 1 | **无** | **无** | **全部** |

低档关掉的只有"让人看出它是个体"和"流动感"两件装饰 —— 剖面轮廓、等压环、
测点球、地层板全在。判断标准是：**这个图元消失后，有没有一条结论跟着消失。**

三条防它自己变成故障的约束：

1. **只降不升。** 升档要重新评估，而重新评估意味着又一次抖动窗口 ——
   在"刚好及格"的机器上，升 → 掉帧 → 降 会变成一个可见的循环。
2. **最多降两档。** 降到底就定住，没有这个终点"一直降"是永不结束的过程。
3. **判据是中位数，不是平均。** 一次 GC 尖峰会把平均值拉过阈值，
   于是在一台本来及格的机器上触发降级。

### 8. 依赖许可证必须允许闭源商用

规则与完整审查结果在 [`docs/licenses.md`](../docs/licenses.md)。
前端 143 个包（含全部传递依赖）零 GPL / AGPL / LGPL / SSPL。

两条经验：

- **必须扫传递依赖。** 直接依赖只有 13 个，而 GPL 的传染性判断看的是整棵树。
- **审查脚本本身要有自检。** 一张写错的正则表会让所有包都判为放行，
  然后 CI 亮着绿灯说"无 GPL"—— 一个替没做的检查背书的绿灯，
  比没有这道检查更危险。`--self-test` 断言名单本身有效。

## 性能：数字与取证

```bash
# 另开一个终端
npm run preview -- --host 127.0.0.1 --port 4173

npm run perf          # 指挥舱，实测帧率 + 逐项渲染开销
npm test              # 降档判定的单元测试（纯函数，不需要浏览器）
npm run licenses      # 依赖许可证审查
```

实测（1680×1000，RTX 5060 Laptop，`?mode=deck`）：

| 指标 | 值 |
|---|---|
| p50 / p95 帧耗时 | 3.3 / 3.4 ms（预算 16.7 ms） |
| draw calls | 30 |
| 三角形 | 5,164 |
| 粒子 | 3,000（**单次** draw call） |
| 几何体 / 纹理 / 着色器程序 | 30 / 5 / 6 |
| 首屏 JS chunk | 291 KB（gzip 99 KB，318,216 字节） |
| three 独立 chunk | 508 KB（gzip 132 KB） |

工程师模式：28 draw calls / 1,964 三角形 / 0 粒子，**渲染循环停止**（只画一帧）。

### 一条实测出来的教训

三个透明网格原来都写了 `side: THREE.DoubleSide`。实测 `renderer.info`：

```
DoubleSide  → 33 draw calls, 8,508 triangles
FrontSide   → 30 draw calls, 5,164 triangles
```

多出的 3 次调用、3,344 个三角形，正好等于三个网格的三角形数之和
（128 + 16 + 3,200）。也就是说**每个 DoubleSide 透明网格都被画了两次**。
而这张剖面上没有任何东西需要看背面 —— 相机固定，只从 +Z 方向看。

> 结论：`renderer.info` 是唯一能证明"这帧很轻"的客观数据。
> 源码里的 `COUNT = 3000` 说明不了问题 —— 3000 个点画 1 次和画 3000 次
> 差三个数量级，而两种写法看起来都很"省"。

### 关于 FPS 这个数字

开发机上 rAF 常常**没有锁 vsync**（远程桌面、虚拟显示器、某些驱动的省电策略），
于是 `fps` 会跑到 300。这时它读作"每帧还剩多少余量"，**不读作"用户看到的流畅度"**。
判据永远是 `p50`：它才是这一帧的真实成本。`measure-fps.mjs` 在 fps > 120 时
会明确打印这条提醒。

## 数据源：三档，且组件不知道区别

| 档位 | 触发 | 说明 |
|---|---|---|
| `fixture` | 默认 | 读 `src/fixtures/*.json`，那是真实接口响应的快照 |
| `live` | `VITE_OPS_SOURCE=live` | 打到 `VITE_OPS_BASE`（默认同源 `/api`），读数用回放样本 |
| `push` | `VITE_OPS_WS` 或 `?ws=` | WebSocket 推送，带退避重连 |

**后门是接上的，不是留了个注释。** 未配置推送地址时不建立任何连接（不是
"假装连上"）；配置之后 `App` 订阅 `alarm` / `thresholds` 两类消息并更新状态，
底栏出现一个连接状态角标。组件始终只拿到 `AlarmReport` —— 它不知道这份数据
是拉来的还是推来的。

断开必须看得见：推送断了而界面照旧显示旧数字，是最难发现的一类故障。
`?ws=` 可以指到一个假服务端做联调：

```bash
node scripts/fake-ws-server.mjs --port 8787        # 零依赖的假推送服务
node scripts/cdp-eval.mjs --url "http://127.0.0.1:4173/?ws=ws://127.0.0.1:8787/" \
  --expr "document.body.innerText.includes('推送已连接')"
```

### live 模式需要有人把读数送进去

`/api/ops/*` 是**无状态**的：它不自己去找时序数据，判定所需的 `readings`
必须由调用方送进去。这个设计是对的（后端不必持有历史库），但它把一个
问题留给了界面 —— live 模式有接口地址，却没有读数可送。

这里踩过一次：`fetchAlarms()` 当时直接 `throw new Error("live 模式下必须
提供 readings")`，而 `App` 的 `Promise.all` 一挂，整个控制台只剩一行
「数据加载失败」—— 左栏 0 张告警、剖面 0 个 canvas、右栏 0 个面板。
`VITE_OPS_SOURCE=live` 这个写在文档里的模式，**一次都没启动成功过**；
fixture 模式一切正常，所以谁也不会发现。

现在 `src/fixtures/readings.json`（`capture_ops_fixtures.py` 生成，非手写）
作为**输入样本**送过去：live 分支跑的是真接口、真计算，只是输入是回放的。
底栏角标因此写的是「live · 读数采样回放」，不写「live」——**输入是录的、
结果是算的，这两件事必须分开说**。接上真实时序采集后，这一行才应该改成
「live · 实时」。

`web/scripts/test-copy.mjs` 里有四条守卫盯着它：live 分支必须存在读数来源、
不能回到那句无人能满足的 `throw`、角标必须写清"采样回放"、`readings.json`
必须非空且字段齐全（删掉它不会让 `tsc` 红，只会让 live 模式打开时炸在一个
运行期的 `Cannot find module` 上）。

### 数据来源 ≠ 后端可达

底栏有两个**分开**的指示器：

| 指示器 | 回答的问题 | 取值 |
|---|---|---|
| 数据来源 | 这份数字从哪来 | `fixture（真实响应快照）` / `live · 读数采样回放` |
| 后端可达性 | 那台机器还活着吗 | 未探测 / 探测中 / 可达 / 降级（几项）/ 不可达 |

`fixture` 模式下界面读本地快照，后端在不在都不影响显示 —— 于是"界面全绿、
数字齐全、后端已经挂了三天"是一个可能的状态，而它读起来像"系统正常"。
两个指示器并排出现，就是为了让这个状态看得见。点一下后端那个角标可以重探
（探针只跑一次的话，界面会永远停在打开页面那一刻的结论）。

探针打 `/health`（**不鉴权**，见 `api_server.py`）：探一个需要 token 的接口，
会把"没配 token"报成"后端挂了"。`404` 与超时也分开报 —— 前者是代理没配，
后者是服务没起，排查方向完全不同。

### 证据强度：三档，不合成一个分数

知识库检索结果与对话里的每条证据都带一个血缘徽标：

| 徽标 | 含义 | 能不能当引用 |
|---|---|---|
| 可溯源 | 切片带 `file_path`，能点回具体文献 | 能 |
| 无文件血缘 | 只有向量召回（Chroma 那 1,982 条的 metadata 只有 `source=legacy_v2`） | **不能**，只能当线索 |
| 公式为主 | 语义邻近，但提供不了机理证据 | 需要另找证据 |

一条切片可以同时犯后两个。合成一个"强度分"之后，界面上只剩一个颜色，
而读者无从知道缺的是哪一项 —— 所以三个数字分开数、分开显示。
`stats.traceable` 这类后端数字会被**逐片重算**：字段改名时 `undefined > 0`
为假，界面会安静地显示"全部可回溯"，而那句结论读起来同样斩钉截铁。

### 对话里的引用从哪来

`/ops/condition` 回答数字（窗口、统计量、越限点数），`/kb/search` 回答出处。
对话把两者并列摆出来，**不合并**：前者每个数字都能在事实块里回代，
后者每片原文都能点开。角标 `[1]` 是检索响应内的序号，不是文献编号 ——
点开的那一屏会明说这件事。

fixture 模式下有一个必须守住的边界：检索快照固定是「盖层完整性对 CO₂ 泄漏
风险的影响」那一次的真实响应。如果用户问的是别的句子，把这份证据挂到回答下面，
会得到一条**看起来有出处、实际出处是别的问题**的回答 —— 这比没有引用糟得多，
因为它把编造从模型搬到了界面上，而且没有任何地方会报错。所以问句对不上快照时
引用一律为空，并把原因写出来。

## 报告审批：一张表、两条路径、一句免责

`draft → pending_review → approved / rejected → draft`。后端
（`ops/reports.py`）早就实现了这套状态机与 sqlite 持久化，缺的一直是界面。

### 那张表必须由后端下发

界面上"哪个按钮能点"取决于当前状态允许哪些迁移。最省事的写法是在 TS 里
再抄一张表 —— 而抄的那一刻起就有了两份真值。之后后端加一条迁移
（比如允许 `approved → draft` 做更正），前端的表不会跟着变，表现是：
**按钮点不动，或者点下去 409**。两种情况都不报错，只在真实审批时被发现，
而那时已经有人在电话里说"我批了"。

所以 `/api/ops/reports/{id}` 多下发两个字段，两个都是前端算不出来的：

| 字段 | 为什么不能由前端算 |
|---|---|
| `draft_id` | `ReportDraft` 不知道自己叫什么（号由 `store` 分配）。没有它，调用方只能"记住自己刚才问了哪个号" |
| `allowed` | 当前状态可执行的动作名（`submit` / `approve` / `reject` / `reopen`），就是端点末段 |

fixture 模式没有后端可写，需要同一张表 —— 于是
`scripts/export_approval_contract.py` **在四个状态上逐个动作真跑一遍**，
把"从哪来、执行什么、落到哪"记进 `fixtures/approval.json`。导出的不是
"我以为的规则"，是"它实际的行为"。CI 里 `--check` 比对：`ops/reports.py`
一改而 fixture 没重新生成就红。

`tests/test_ops_reports.py::ActionTargetTests` 用同样的探针锁住
`ACTION_TARGETS` 这张**声明**：表里写的目标必须等于真跑一次之后落到的状态。

### 演练与真审批的差别，写在脸上

| | `fixture`（默认） | `live` |
|---|---|---|
| 草稿来源 | `fixtures/reports.json`（真实端点产出） | `/api/ops/reports` |
| 迁移执行者 | 本机（`lib/approval.ts::applyAction`，纯函数） | 后端 |
| 轨迹存放 | 这个浏览器的 `localStorage` | `ops_reports.db` |
| 刷新 | 不丢 | 不丢 |
| 跨班次 / 跨设备 | **不能** | 能 |

面板顶部常驻一句话：**本机演练 · 轨迹存在这个浏览器里，刷新不丢；但不是
审计记录，不跨班次、不跨设备。** 把这句话藏起来，等于让一次演练看起来像
一次真实审批 —— 而审批的全部价值就在于它能被追溯。

浏览器不允许本地存储时（Safari 无痕、企业策略），界面照实说"刷新就会丢"，
不显示"已保存"。

### 正文里不写审批状态

原先报告模板最后一节是「状态：草稿」。`build_daily` / `build_weekly` /
`build_regulatory` 全部在提交之前调用，所以那里的 `draft.status` **恒为草稿** ——
每一份已批准的稿子都会印着「状态：草稿」。

而正文是要归档的。读者在报告记录（已批准）和文件正文（草稿）上看到两个
相反的说法时，会相信印在文件上的那一个，于是"审批"在档案里等于没发生过。

现在那一节改成一句话说明状态去哪了，并有
`BodyDoesNotFreezeStatusTests` 锁住（三种报告都查）。

### 三条守卫，都不能只置灰

| 守卫 | 拒绝时说什么 |
|---|---|
| 引用检查未过 | 逐条列出「第几行的哪个数字没有出处」，并说明"批准这样的稿子等于背书" |
| 批准必须署名 | 不预填上次的名字 —— 批准人必须自己确认这次是谁在批 |
| 驳回必须写意见 | 说明后果（下一稿会原样再来一遍），而不是只说"必填" |

理由显示在按钮**下面**，不只塞进 `title`：触屏上没有 hover。文案逐字取自
后端（`fixtures/approval.json` 的 `guards`），前端不另写一份。

### 它不在首屏的 chunk 里

审批面板连同 28 KB 的草稿 fixture 一起，是切到「报告」页签时才拉的独立
chunk（`ApprovalPanel-*.js`）。首屏要看的是左栏告警与中央剖面 ——
"要不要叫人"这件事不该等审批面板的代码。CI 有一条守卫断言它仍然分块。

### 草稿从哪来：`/api/ops/run`

这一页原来只能读已有的草稿，而草稿只有命令行能生成 —— 于是 live 模式下
它永远是空的（"还没有报告草稿"），审批状态机再完整也没有输入。现在页签
顶部有一个「生成草稿」：选种类（日报 / 周报 / 监管材料），点一下，ops
主管 agent 现场跑「告警判定 → 报告撰写 → 跨 agent 冲突检测」，草稿落进
`ops_reports.db`，随后提交 / 批准 / 驳回都按同一个 `draft_id` 走。

`ops/run` 是**确定性**的（不调模型），实测 65 ms —— 但它不是"导出"：
界面上必须让人看见哪几个 agent 跑了、各用了多久、有没有失败。所以生成
之后显示的是三样东西，缺一样"已生成"就成了无法核对的话：

| 显示 | 回答的问题 |
|---|---|
| `2 个 agent 执行完毕 · 3 项偏离（均非阻断）` | 跑了几步、成了几步 |
| 逐条 `✓ alarms · 0.00s · 判定基础` | 哪一步、为什么派它、耗时 |
| `阻断｜…` / `提示｜…` | 有没有一条冲突意味着"这份稿子不能提交" |

**阻断性冲突必须单独计数**。压成「3 项偏离」之后，其中那条"不能提交"
就和两条无害的提示长得一样了。

读数送的是抓 fixture 时录下的那批（`readings.json`），所以生成出来的
报告**不是当期实测** —— 这句话跟着结果显示（`读数取自回放样本（…），
不是当期实测。`）。不写的话，一份写着"2026-10-27 06:00–10:00"的日报
会被当成今天的日报读。

演示模式下按钮**在动手之前就禁用**，并写清为什么（"报告要由 agent 现场
生成，没有可复用的快照"）。让它看起来成功，等于让人以为自己的操作被记下了。

监管材料多一个许可证号输入框：后端对 `permit_id` 为空直接 400。先在
界面上拦住，并把原因写在按钮旁边 —— 让人打完字点一下、看到一句 400 的
JSON，是同一件事的更差版本。

## 知识库从「只读」到「可记录」：反馈能落地，但不假装能修

界面原来只有看的份：发现"这篇论文没进图谱"、"这个问题检索答不了"，能做的只有
记在心里。现在每条缺口旁边有一个「登记」按钮，检索没答到时也有入口 —— 它把一句
人能看懂的话写进队列（`history/kb_gaps.jsonl`，一行一条，不进仓库）。

三件事刻意做得和"一键修复"不一样：

1. **不触发入库。** 入库要跑 `ingest_ccus_batch.py`（占满一张显卡、几十分钟），
   建图更慢。所以提交后的文案是**后端给的**（`api_kb.GAP_NEXT_STEP`），
   写清"进的是人工队列，不会自动重建索引"。承诺放在后端只有一个理由：
   分散在三个组件里时，总有一份会说成"稍后自动处理"。
2. **说不出对象的反馈不收。** `not_in_graph` 必须带文件名、`wrong_evidence`
   必须带当时的问题 —— 否则处理它的人第一步只能回来问反馈的人，那比没有反馈
   更费时间。后端直接 400，文案原样显示在界面上（换成"提交失败"用户只能重试，
   而他需要的是改）。
3. **演示模式不落盘。** 审批轨迹存 `localStorage` 是对的（那是你自己的演练，
   刷新不丢就有意义），缺口反馈不一样 —— 它的全部价值在于送到维护语料的人手上，
   存在浏览器里等于没写。所以按钮在用户**动手之前**就是禁用的，旁边写着为什么。
   让他打完一百字才告知"其实没发出去"是同一类欺骗的另一种形式。

队列要显示出来（`已登记 N 条 · 这篇没进图谱 2 · 检索没答到 1`），因为"提交成功"
三个字没法区分"记下了"和"按钮点了没反应"。读不到队列时说**读不到**，
不说"0 条" —— 0 条是一个关于人的结论，读不到是一个关于文件系统的结论，
而把后者渲染成前者是唯一不会报错的失败。

`unavailable` 状态**不给**登记入口：这时检索根本没跑起来，登记一条"没答到"会把
一次服务故障记成语料缺口，队列里那个数字随后会被当成"该补文献了"。

表单是 `React.lazy` 的（点了「登记」才拉，独立 chunk `KbGapForm-*.js`）。
加进首屏时首屏 chunk 从 313,364 涨到 318,649，离 320,000 的守卫线只剩 1.3 KB ——
拆出来是 316,879。差别不大，但方向要对：一个只在点击后出现的表单不该占首屏预算。

## 测点全量表：同一份 18 行数据的第二种读法

左栏的卡片按**严重度**排，回答的是"我该先处理哪一条"。它不回答另一个问题：
**18 个测点里，哪几个离自己的线最近？** 卡片里每一张的"阈值 / 余量"是同一行
文字，横向扫不起来；`notice` 那几条被夹在中间，看起来和 `normal` 一样。

工程师模式多一个「表格」切换（指挥舱没有：18 行小字在投影上什么也读不出来）。
表格把这些变成同构的四列：测点 / 读数 / 距 warn 线 / 状态。

### 一列「距 warn 线」，两个方向

"上限"对每个测点含义不同：`high` 方向是 warn 上方的线，`low` 方向是下方的线。
统一成**负 = 已越线**（`high` 是 `warn − value`，`low` 是 `value − warn`）之后，
一列就能横向比较，不必按方向分两张表。**具体命中了哪一级**由状态列回答。

余量的基准是 **`warn → alert` 的带宽**，不是阈值的百分比。`co2_purity` 的
warn=95、量程上限 100 —— 按"warn 的 10%"算出来的基准是 9.5，而 95 往上只剩 5，
于是同一个"刚过线一格"的读数在这条测点上显示 −0.105、在 `annulus_pressure`
（warn=20、alert=30）上显示 −0.5。两条读数对现场的意思是一样的，尺子必须一致。
带宽 ≤ 0（配置本身有问题）时**不给比例**，而不是给 0 —— 0 会被读成"贴着线"。

### 三种「不知道」在同一张表里的样子

| 情形 | 余量列 | 状态列 | 悬停说明 |
|---|---|---|---|
| 有读数、有阈值 | `余 1.6` / `超 1.6` | 六级之一 | 方向 + warn 值 |
| 有读数、没配阈值 | `—` | `不可判定`（虚线下划线） | 未配置阈值 |
| 有阈值、没读数 | `—` | `不可判定` | 没有可信读数 |
| 告警里有、目录里没有 | `—` | `不可判定` | 测点目录里没有它 |

第四种是"不能丢掉这一行"：丢掉等于把一个真实告警藏起来，编一个阈值更糟。
状态列用**虚线下划线**而不是换个颜色 —— 色觉障碍、强光、灰度打印都会让
"灰"和"浅灰"变成同一个东西。表格底部必须写一句"不可判定的 N 项与「正常」
不同：它们是「没人说过多少算有问题」，不是「没问题」"：破折号在"没有读数"
那一行也出现，两种"不知道"混在一起会被读成"这三个没数"。

### 18 行也要窗口化

不是为了省渲染（18 行怎么渲染都不慢），而是因为**行数是数据属性**：目录来自
`config/ops_thresholds.json`，换一个测点更密的场地（管线每 10 km 一个测点、
多井场）就是几百行，而这块屏的用途是"扫一眼"。更实际的理由是窗口化的边界
（第一行、最后一行、滚过头）比"能不能显示"更容易写错 —— 所以
`lib/sensorTable.ts` 的 `visibleRange()` 是纯函数，`scripts/test-sensors.mjs`
直接断言，不需要起浏览器。

行高是常量（`ROW_HEIGHT = 22`），窗口化按 `top = index × ROW_HEIGHT` 定位；
行高一变，滚动条位置与渲染区间就对不上，表现为"滚到某处会跳一下"。所以行内
文字一律 `truncate`，不做换行。越界一律夹住：滚动容器的 `scrollTop` 在惯性
滚动时会短暂超过内容高度（移动端回弹），那时渲染出空区间会让表格闪一下空白。

### 视图由 mode 收口，不是只把按钮藏起来

指挥舱不显示切换按钮，但**表格本身也必须不显示**。只藏按钮会留下一个回不去的
状态：工程师模式切到表格 → 切到指挥舱 → 表格还在，而切回去的按钮已经不在了，
读者会以为指挥舱本来就这么显示。`const shownView = mode === "engineer" ? view : "cards"`
是唯一出口；`test-copy.mjs` 有一条源码守卫锁着它（静态渲染测试不点按钮，抓不到）。

表格是 `React.lazy` 的（点了「表格」才拉，独立 chunk `SensorTable-*.js`）。
静态 import 时首屏从 317,615 涨到 321,021，直接顶破 320,000 那条线 ——
撞线时该拆，不该改数字。

## 自检

```bash
npm run typecheck    # tsc -b --noEmit
npm test             # 167 项：降档判定 / 文本清洗 / 角标解析 / 证据强度 / 处置标记 / 审批状态机 / 缺口反馈 / 测点表判定 / 报告生成判定 / 数值一致性 / 文案守卫 / 标签避让 / 组件渲染冒烟
npm run build        # 首屏 chunk 必须 < 320 KB（CI 有守卫）
```

`npm test` 里的渲染冒烟（`scripts/test-render.mjs`）用 esbuild 把组件打成一个
临时 ESM，再用 `react-dom/server` 渲染成 HTML 断言文字。它不检查样式，
但能抓住三类真实故障：初始渲染抛异常（白屏）、某个分支永远不渲染（面板空白）、
关键措辞消失（结论没显示）。截图能证明"看起来对"，但它需要一台能起窗口的机器 ——
起不了 GUI 的环境里，截图脚本会静默挂住，最后谁都不跑它。

`scripts/test-copy.mjs` 断言的是**源码文本**，故意不渲染。它守的五件事都是
"被一次'这句太长了，简化一下'的重构删掉"的类型，逻辑测试抓不到：
剖面图例的三种渲染状态标签、羽流与分层必须声明为示意值、限制说明里
"不能作为井位设计 / 封存容量 / 压力预测"这三句、无血缘的引用不得渲染成可点按钮、
测点表的视图必须由 `mode` 收口（只藏按钮会留下一个回不去的状态）。
断言"说清了什么"而不是"用了哪个词"：`不能` 与 `井位设计` 分开查，改语序不会红。

`scripts/test-labels.mjs` 测 `placeLabels()` 的坐标。它是纯函数（不碰 DOM、
不读时间），所以可以直接断言"推开之后两个矩形还相交吗"。这一点很要紧：
标签避让**没接上**和**接上了但算错**在截图上长得一模一样，都是重叠。
9 条断言里有一条专门锁"固定的标签排在后面时也必须被避开"——那个顺序 bug
实测出现过一次，而它的表现只是"右上角有个 `0 m` 压在测点标签上"。

`scripts/test-sensors.mjs` 测测点表的判定（30 条）。它守的同样是"错了不报错"的
一类：余量符号反了最危险的测点会排到最后、没有阈值被算成 0 会落在"贴着线"的
位置、窗口化边界算错则滚到底时最后几行永远不渲染。还有一条专门锁
`formatMargin` 的尾零裁剪 —— 裸的 `toFixed(0).replace(/\.?0+$/, "")` 会把
`100` 变成 `1`，而余量 100 bar 与余量 1 bar 是两种工况，屏幕上只差两个字符。

`scripts/test-run.mjs` 测「生成草稿」这一动作（16 条）。它是界面上唯一会
新建记录的按钮，失效方式全是安静的：演示模式下也能点、一个 agent 失败却
只说「已生成」、阻断性冲突被压成「3 项偏离」、回放读数被写成当期实测。
live 那一半用 `fetch` 桩断言它真的发 `POST /api/ops/run`、真的带上读数、
真的把后端 400 的文案透出来 —— 只测纯函数会漏掉"按钮接错了端点"。

`scripts/test-numbers.mjs` 测**数值显示的一致性**（10 条）。它守的是一件
很具体的事：卡片上并排的三个数必须能心算对上。

```
储层监测压力   296bar
阈值 300 · 余量 3.68     ← 296 + 3.68 = 299.68，差 0.32
```

两个数都没错，但放在一起就是错的 —— 一个按 0 位小数显示，一个按 2 位。
审计的人第一眼就抓这个，然后开始怀疑别的数字。修法是让余量跟**读数**用
同一把尺子（`digitsForValue`）：读数 296 是 0 位，余量就显示 4。代价是
3.68 变成 4（在 300 的尺度上是 0.1%），换来屏幕上那行算术真的成立。

测试用一条**性质断言**覆盖全部 fixture 测点：显示出来的读数 ± 显示出来的
余量，必须落在显示出来的那条线上（误差不超过半个末位）。四个方向组合
（high/low × 未越限/已越限）都要过 —— 只举一个例子会漏掉越限之后基准
换成"被越过的那条线"那一支。

同一份测试还锁了两件小事：`0.004` 不能显示成 `0`（`toFixed(2)` + 裁尾零
会把它变成零，一个真实读数被显示成零是这张卡最不能犯的错）；pH 这类
无量纲测点的 `unit` 是 `"-"`，直接拼会得到「7.18-」，读起来像负数或
被截断的区间。
